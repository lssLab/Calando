# パフォーマンスと常駐メモリ

<p align="center">
  <a href="performance.md">English</a> · <a href="performance.ko.md">한국어</a> · <a href="performance.zh-CN.md">简体中文</a> · <strong>日本語</strong>
</p>

Memory Supervisor は 1 つの同期 Rust 実行可能ファイルを使用します。 バックグラウンド測定や hook 決定のために、別個の言語ランタイムや常駐 worker プールは開始されません。

<a id="measured-native-release-builds"></a>
## 測定されたネイティブ リリース ビルド

各行には、ウォームアップ後に 0.2 秒間隔で取得された 20 個のサンプルが含まれています。 WSL2 行は、インストールされているサービスを測定します。 CI 行は、一致するプラットフォームの実行可能ファイルを測定します。

| 環境 | 常駐メモリの最小 / 平均 / 最大 | スレッドの最小値と最大値 | ストリップされた実行可能ファイル |
| --- | ---: | ---: | ---: |
| WSL2 Linux、物理サービス | 4.88 / **4.88** / 4.88 MiB RSS | 1 | 1.65 MiB |
| Ubuntu x86-64、CI | 3.50 / **3.52** / 3.54 MiB RSS | 1 | 1.69 MiB |
| Windows x86-64、CI | 4.15 / **4.20** / 4.25 MiB ワーキング セット | 4–6 | 1.34 MiB |
| Apple Silicon macOS、CI | 3.38 / **4.35** / 5.13 MiB RSS | 1–3 | 1.41 MiB |

通常の制御ループはシングルスレッドです。 追加の CI スレッドは、オペレーティング システムのセンサー コマンドがアクティブな間のみ存在する制限付きリーダーです。 測定されたすべての最大値は、インスタンスあたりの計画許容値 10 MiB を下回っています。

<a id="why-it-stays-small"></a>
## なぜ小さいままなのか

- 1 つの実行可能ファイルは、daemon、hook のゲート、ステータス、制御、通知、および統合機能を実装します。
- 通常の daemon ループは同期です。 Tokio ランタイムまたは常駐 worker プールはありません。
- Linux および macOS hooks は、有効な間、低速パスを開始せずに、短い正常な状態のリースを使用します。
- Windows は、グローバル メモリ カウンターを毎秒読み取りながら、高価なプロセス インベントリのみを 3 秒間キャッシュします。
- オペレーティング システムのセンサー コマンドとリーダー スレッドは、制限された呼び出し中にのみ存在します。

<a id="interpreting-the-measurements"></a>
## 測定値の解釈

RSS および Windows ワーキング セットはオペレーティング システムのアカウンティング値であり、バイト単位で固有の物理ページではありません。 プロセス数とネイティブ センサーの実装により、結果が変化する可能性があります。 容量計画には、測定された最小サンプルではなく、**インストールされている supervisor インスタンスごとに 10 MiB** を使用します。 Windows、各 WSL ディストリビューション、各 VM、および分離された各コンテナーは独自のインスタンスを実行するため、常駐メモリは個別に追加されます。

正常状態の hook 高速パスは、daemon の短い現在の決定が有効である間のみ使用されます。 期限切れまたはパスの不一致の決定は Rust ゲートにフォールバックし、ローカルおよびフェデレーションの状態が再度検証されます。 これにより、停止した daemon が古い健全な決定をアクティブのままにすることを防ぎます。
