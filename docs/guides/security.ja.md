# セキュリティとデータ/コントロールの境界

<p align="center">
  <a href="security.md">English</a> · <a href="security.ko.md">한국어</a> · <a href="security.zh-CN.md">简体中文</a> · <strong>日本語</strong>
</p>

このドキュメントには、Memory Supervisor が読み取り、ローカルに保存し、1 台のコンピューター上の環境間で共有する情報のすべてのカテゴリがリストされています。 また、オプションの通知によって使用されるネットワーク アクセスと正確な制御制限についても説明します。 テーブルは製品の完全なデータと制御境界です。 それ以外の情報やプログラムは扱われません。

| エリア | 何を読むか、何をするか | 明示的なストレージ、共有、および制御境界 |
| --- | --- | --- |
| システムメモリ | オペレーティング システムの物理メモリ、利用可能なメモリ、コミットされたメモリの合計を読み取ります。 減少率; 記憶のプレッシャー。 再利用、スワップ、およびページングアクティビティ。 および該当するコンテナーのメモリ制限。 | メモリの内容を読み取ったり、RAM、スワップ、コンテナの制限、仮想マシンのメモリ設定を変更したりすることはありません。 |
| 実行中のプロセス | 現在のアクセス許可レベルで表示される実行可能ファイルとコマンドラインのメタデータ、PID、親関係、開始 ID、ターミナル、メモリ使用量、増加率を読み取り、Claude Code、Codex、およびそれらの child の動作を識別します。 | プロセス メモリの内容やプログラムによって開かれたファイルを読み取ることはなく、完全な生のプロセス コマンド ラインを状態に保持することもありません。 Chrome や IDE などの無関係なプログラムの場合は、帰属に必要なオペレーティング システムのプロセス メタデータのみを読み取り、制御しません。 |
| Claude Code および Codex hooks | hook プログラムは各イベント JSON を一時的に受信し、プロバイダー、hook イベント、セッション、会話スレッド、エージェント、ターン、タスク、およびツールの識別子とタイプのみを抽出します。 App Server ルーティングデータ。 作業ディレクトリ。 開始されるコマンドの最大で最初の 2,048 文字。 そして制限レシート。 | イベントにプロンプ​​ト、会話またはモデル テキスト、または編集用のファイル コンテンツが含まれている場合でも、それらのフィールドは制御に使用されず、ローカル状態、federation、Discord または Telegram 通知に配置されません。 Claude または ChatGPT 資格情報ストアまたはトークンを照会しません。 コマンド ラインに直接入力されたシークレットは、抽出されたローカル コマンド プレフィックスに表示される可能性があるため、シークレットをコマンド ラインに配置しないでください。 |
| ローカルストレージ | 構成、メモリの決定、プロセスとエージェントの状態、アクションと回復の履歴、hook の健全性、および通知設定をユーザーのプロファイルに保存します。 | プロジェクト ファイルには書き込みません。 生の作業ディレクトリとコマンド プレフィックスはローカルに残り、Discord や Telegram 通知では送信されません。 |
| 同じマシン federation | 各環境は、現在のメモリ、プレッシャー、およびアクションの状態を公開します。 プロセス、端末、およびエージェントの識別子。 アプリ hook のパスと健康状態。 インシデントとリカバリの状態を同じローカル共有フォルダーに保存します。 ピアは、新しい作業 admission を調整するために 10 秒以内に更新された状態のみを使用します。 | 各モニターは、独自の環境内のプロセスのみを制御します。 別の物理コンピューターまたはクラウドサーバーからのネットワーク共有と状態は、federation には使用されません。 未処理の作業ディレクトリとコマンド プレフィックスは、フェデレーテッド状態には含まれません。 |
| ネットワークと通知 | 通常の監視では外部要求は行われません。 インストールとアップデートは、GitHub からファイルをダウンロードします。 有効になった OS 通知はコンピューター上に残ります。 有効な Discord および Telegram ルートは、サニタイズされたメモリ状態、アクション、理由、および該当する場合はターゲット PID を送信します。 セットアップ コマンドとテスト コマンドは、選択したサービス API に接続します。 | このプロジェクトには、収集サーバーや使用状況テレメトリがありません。 通知資格情報はローカル構成に残り、ステータス出力ではマスクされます。 プロンプト、会話テキスト、生のコマンド、プロジェクト ファイルは送信されません。 |
| 新規作業制御 | 起動前に、hooks は、新しい subagent、ツール、ビルド、テスト、またはその他の高メモリ コマンドを許可または遅延し、選択したエージェントの今後の作業のみを段階的に絞り込むことができます。 | すでに進行中の編集、応答、結果配信はキャンセルされません。また、端末にコマンドを入力することもありません。 |
| プロセス制御 | 最後の手段としてのみ、Claude Code または Codex に属すると再検証された 1 つのローカル ワーク プロセスを一時停止し、安定した回復後にプロセスを 1 つずつ再開します。 動作する直前に PID を再チェックし、ID を開始します。 | 自動的に終了したり強制終了したりすることはなく、別の環境にある別のプログラムや PID を一時停止したり終了したりすることもありません。 `terminate` と `kill` は、ユーザーが明示的に実行した場合にのみ機能します。 |
| Lead-エージェントの保護 | lead は、段階的な新規作業の遅延と subagent およびツール制御、およびその同じ lead からの持続的な成長、その正確なプロセス、およびそのターミナルのすべてが確認された後、危険が残るまれな場合にのみ停止します。 | lead の一時停止は、通常の記憶を圧迫するアクションではありません。 それは最後の保護段階です。 lead は、その端末が通知を受信できない場合には一時停止されません。 |
| 端末とleadの通知 | 制限の理由と回復状態を検証済みの端末に書き込み、同じ決定を次の hook まで lead に送信します。 | 端末入力の読み取り、コマンドの挿入、端末設定や入力モードの変更は行いません。 |
| インストール、アップデート、削除 | ユーザースコープの実行可能ファイルまたはソース、ユーザーバックグラウンドサービスと自動開始エントリ、所有されているhookとスキル接続、構成ファイルと状態ファイルのみをインストール、更新、または削除します。 | プロジェクト ファイル、カーネル、ドライバー、ファイアウォール、オペレーティング システムのメモリやスワップ設定は変更されません。 削除は、ユーザーが明示的に `uninstall` を実行した場合にのみ開始されます。 |
| ユーザーが選択した設定 | デフォルトでは固定メモリ上限はありません。 `budget set`、`on`、`off`、手動`resume`、`terminate`、`kill`、および通知設定は、ユーザーがこれらのコマンドを実行した場合にのみ変更されます。 | オプションのキャップや終了コマンドは自動的には有効になりません。 |
| 安全対策 | 欠落している、または古い hook 決定は破棄され、作業は通過し、保護は利用できないと報告されます。 PID と開始 ID はプロセス制御の前に再チェックされます。 lead は、その正確な端末が通知を受信できない限り一時停止されません。 アクション記録を保存できない場合、アクション記録は一時停止されません。 | 古い決定が作業を妨げたり、記録されない一時停止が残ったりすることはありません。 自動物理アクションは、検証済みの Claude Code または Codex の作業プロセスの可逆的な一時停止を超えることはありません。 |

**Memory Supervisor は、この表にリストされているもののみを検査および制御します。** プロジェクト ファイルやプロセス メモリを直接開くことはありません。 hook イベント内で到着する可能性のあるプロンプト、会話、モデル応答、およびファイルコンテンツフィールドは、抽出または制御に使用されず、ローカル状態に保持されず、federation を通じて共有されたり、外部通知で送信されたりしません。 ブラウザと IDE の内部データ、および Claude または ChatGPT 資格情報もその境界外にあります。
