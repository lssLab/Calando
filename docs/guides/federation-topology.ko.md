# 한 컴퓨터의 여러 환경을 연결하는 Federation

<p align="center">
  <a href="federation-topology.md">English</a> · <strong>한국어</strong> · <a href="federation-topology.zh-CN.md">简体中文</a> · <a href="federation-topology.ja.md">日本語</a>
</p>

Memory Supervisor는 자기 프로세스를 보고 제어할 수 있는 운영체제 커널마다 하나씩 실행됩니다.
Federation은 한 컴퓨터 안의 여러 커널이 같은 물리 메모리를 함께 쓸 때 각 Supervisor의 판단을
맞춥니다.

## 판정 기준

두 환경은 다음 조건을 모두 만족할 때만 연결됩니다.

1. 두 환경의 메모리 증가가 같은 물리 RAM을 사용합니다.
2. 같은 컴퓨터임을 입증하는 host-local 공유 폴더에서 만날 수 있습니다.

Federation은 현재의 새 작업 허용 판단만 공유합니다. 메모리를 하나로 합치거나 작업을 옮기지 않으며,
한 커널이 다른 커널의 프로세스 번호를 제어하도록 만들지 않습니다.

## 환경별 동작

| 환경 | Host RAM을 동적으로 함께 쓰나? | Federation 동작 |
| --- | --- | --- |
| 네이티브 Linux·macOS·Windows | 두 번째 커널이 없음 | 로컬 Supervisor만 사용 |
| WSL2와 Windows host | 예 | Host 파일시스템에서 만나 새 작업 판단 공유 |
| 여러 WSL2 배포판 | 예 | 같은 host 파일시스템에서 서로 연결 |
| Host와 일반 container | 예 | 같은 host-local 폴더를 마운트한 경우 연결 |
| 메모리 balloon이 있는 동적 VM | 예 | Host-local 공유 폴더가 있을 때 연결 |
| 고정 메모리 VM | 아니오, 메모리가 분리됨 | Guest가 독립적으로 동작 |
| Cloud VM 또는 다른 물리 컴퓨터 | 관리 가능한 공유 RAM이 없음 | 각 컴퓨터가 독립적으로 동작 |

두 컴퓨터가 같은 네트워크 위치를 읽을 수 있다는 이유만으로 Federation peer가 되지는 않습니다.
네트워크 공유 폴더는 같은 물리 메모리를 쓴다는 증거가 아닙니다.

## 감지와 공유 위치

프로그램은 세 가지를 분리해서 판단합니다.

```text
OS 어댑터        -> 이 커널에서 메모리를 측정하고 확인된 로컬 PID를 제어하는 방법
AI 어댑터        -> Claude Code·Codex의 세션, 에이전트와 도구를 구분하는 방법
위상 어댑터      -> 어떤 커널이 RAM을 함께 쓰며 어디에서 상태를 교환하는지
```

WSL2는 마운트된 Windows host 파일시스템을 사용합니다. Container는 명시적으로 마운트한 host-local
폴더를 사용합니다. 동적 VM은 사용할 수 있는 hypervisor 공유 폴더를 사용하며, 그런 폴더가 없으면
자기 환경만 관리합니다. Linux guest는 지원되는 메모리 balloon 장치가 있으면 동적 VM, 없으면 고정
메모리 VM으로 판정합니다.

`memory-status --all`은 감지된 환경과 각 환경이 제공한 판단을 보여줍니다. 정해진 시간 안에 갱신된
상태만 현재 판단에 참여합니다.

## 공유되는 정보와 공유되지 않는 정보

Federation 상태에는 보호 판단에 필요한 정보만 들어갑니다.

- 메모리 용량·여유·압력·증가 또는 감소 속도
- 현재 새 작업 허용 수준과 복구 상태
- 진단에 필요한 환경·프로세스·터미널·논리 에이전트 식별 정보
- Hook 연결 상태와 아직 전달되지 않은 보호 사건 상태

프롬프트, 대화, 모델 응답, 프로젝트 파일 내용, 전체 명령줄, 인증 정보와 알림 비밀값은 넣지
않습니다. 각 Supervisor는 자기 커널 안에서 다시 확인한 프로세스만 일시정지하거나 재개할 수 있습니다.

## 같은 컴퓨터인지 확인하는 방법

공유 폴더는 물리 host에 로컬이어야 합니다. Linux는 네트워크 파일시스템 종류를 거부하면서 WSL2의
host 파일시스템 같은 로컬 마운트는 허용합니다. macOS는 로컬 파일시스템 표시를 확인하고 Windows는
UNC 경로와 원격으로 연결된 드라이브를 거부합니다.

환경이나 경로가 모호하면 원격 peer를 신뢰하지 않고 해당 환경을 독립적으로 처리합니다. 이 경우
환경 사이의 판단 공유를 놓칠 수는 있어도 다른 컴퓨터의 프로세스를 잘못 제어하지는 않습니다.

## 여러 터미널을 함께 사용할 때

한 커널 안의 여러 터미널은 이미 로컬 Supervisor 하나가 함께 관찰합니다. 터미널 수만큼 데몬을
만들거나 메모리를 중복 합산하지 않습니다. Windows·WSL2·container·동적 guest처럼 같은 컴퓨터에
다른 커널이 추가되면 각 커널에 Supervisor 하나가 실행되고, Federation은 새 작업 판단만 맞춥니다.

공유 자원에는 갱신된 판단 중 가장 보수적인 새 작업 허용 수준을 적용합니다. 프로세스 제어는 계속
로컬이며 선택적입니다. 한 Supervisor가 다른 환경의 PID에 신호를 보내는 일은 없습니다.

설정 방법은 [플랫폼 배포](platforms.ko.md), 검증 범위는
[테스트 표](../testing/test-matrix.ko.md)를 참고하십시오.
