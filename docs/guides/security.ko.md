# 보안과 데이터·제어 경계

<p align="center">
  <a href="security.md">English</a> · <strong>한국어</strong>
</p>

이 문서는 Memory Supervisor가 확인하는 정보, 로컬에 저장하는 정보, 같은 컴퓨터 안에서
공유하는 정보, 선택 알림이 사용하는 네트워크와 실제 제어 범위를 한곳에 정리합니다. 아래 표가
제품의 전체 데이터·제어 경계이며, 표 밖의 정보나 프로그램은 다루지 않습니다.

| 영역 | 확인하거나 실행하는 일 | 저장·공유·제어의 명확한 경계 |
| --- | --- | --- |
| 시스템 메모리 | 운영체제가 제공하는 전체·가용·커밋 메모리, 감소 속도, 메모리 압력, 회수·스왑·페이지 이동 수치와 적용되는 컨테이너 메모리 한도를 읽습니다. | 메모리 안의 내용은 읽지 않으며 RAM·스왑·컨테이너 한도·가상 머신 메모리 설정을 바꾸지 않습니다. |
| 실행 중인 프로세스 | 현재 권한으로 보이는 프로세스의 실행 파일·명령줄 정보, 번호(PID)·부모 관계·시작 정보·터미널, 메모리 사용량과 증가 속도를 읽어 Claude Code·Codex와 그 하위 작업을 구분합니다. | 프로세스 메모리의 내용이나 프로그램이 연 파일은 읽지 않습니다. 전체 명령줄 원문은 상태 파일에 저장하지 않습니다. Chrome·IDE 같은 다른 프로그램은 원인 판별에 필요한 운영체제 프로세스 정보만 확인하며 제어하지 않습니다. |
| Claude Code·Codex Hook | Hook 프로그램은 Claude Code·Codex가 보내는 이벤트 JSON을 순간적으로 받은 뒤 프로그램 종류, Hook 발생 시점, 세션·대화 스레드·에이전트·작업·도구 번호와 종류, App Server 연결 정보, 작업 폴더, 실행할 명령의 앞부분 최대 2,048자, 제한 적용·확인 상태만 추출합니다. | 이벤트에 프롬프트·대화·모델 응답이나 편집할 파일 내용이 포함되더라도 해당 필드는 제어 판단에 사용하지 않고 로컬 상태·federation·Discord·Telegram 알림 어디에도 넣지 않습니다. Claude·ChatGPT 인증 저장소와 토큰도 조회하지 않습니다. 다만 명령줄에 직접 넣은 비밀값은 추출 대상인 로컬 명령 앞부분에 포함될 수 있으므로 명령줄에 비밀값을 넣지 않아야 합니다. |
| 로컬 저장 | 사용자 프로필 아래에 설정, 메모리 판단, 프로세스·에이전트 상태, 조치·복구 기록, Hook 연결 상태와 알림 설정을 저장합니다. | 프로젝트 파일에는 기록하지 않습니다. 작업 폴더와 명령 앞부분 원문은 로컬에만 두고 Discord·Telegram 알림에는 보내지 않습니다. |
| 같은 컴퓨터의 federation | 각 환경이 같은 로컬 공유 폴더에 현재 메모리·압력·조치, 프로세스·터미널·에이전트 식별 정보, App Hook 연결 경로·상태와 사건·복구 상태를 게시합니다. 다른 환경은 10초 안에 갱신된 상태만 읽어 새 작업 허용 수준을 맞춥니다. | 각 감시 프로그램은 자기 환경의 프로세스만 제어합니다. 네트워크 공유 폴더와 다른 물리 컴퓨터·클라우드 서버의 상태는 federation에 사용하지 않습니다. 작업 폴더와 명령 앞부분 원문은 federation 상태에 넣지 않습니다. |
| 외부 통신과 알림 | 평상시 감시는 외부 통신을 하지 않습니다. 설치·업데이트는 GitHub에서 파일을 받습니다. 사용자가 켠 운영체제 알림은 컴퓨터 안에서만 표시되고, Discord·Telegram 알림은 정리된 메모리 상태·조치·이유와 대상이 있을 때 그 PID를 보냅니다. 외부 알림 설정·시험 과정에서는 해당 서비스 API에 연결합니다. | 이 프로젝트가 운영하는 수집 서버나 사용 통계 전송 기능은 없습니다. 알림 인증 정보는 로컬 설정에 보관하고 상태 출력에서는 가립니다. 프롬프트·대화·명령 원문·프로젝트 파일은 보내지 않습니다. |
| 새 작업 제어 | Hook이 새 서브에이전트, 도구, 빌드·테스트 같은 고메모리 작업을 시작하기 전에 허용하거나 잠시 미루고, 선택된 에이전트의 앞으로 할 일만 단계적으로 줄입니다. | 이미 진행 중인 편집·응답·결과 전달은 취소하지 않고 터미널에 명령을 입력하지 않습니다. |
| 프로세스 제어 | 최후 수단에서만 Claude Code·Codex 소속으로 다시 확인된 로컬 작업 프로세스 하나를 일시정지하고, 안정되면 하나씩 재개합니다. 직전에 PID와 시작 정보를 다시 확인합니다. | 자동 종료·강제 종료는 하지 않으며, 다른 프로그램이나 다른 환경의 PID는 일시정지·종료하지 않습니다. `terminate`·`kill`은 사용자가 명령을 직접 실행한 경우에만 동작합니다. |
| 리드 에이전트 보호 | 새 작업 대기와 서브에이전트·도구 제어 뒤에도 위험이 계속되고, 같은 리드의 지속적인 메모리 증가, 정확한 프로세스와 터미널이 모두 확인된 희소 상황에서만 리드를 일시정지합니다. | 리드 일시정지는 일반적인 메모리 압력 조치가 아니라 최후의 보호 단계입니다. 정확한 터미널에 알림을 남길 수 없으면 리드를 멈추지 않습니다. |
| 터미널과 주 에이전트 알림 | 확인된 터미널에 제한 이유와 복구 상태를 표시하고, 다음 Hook에서 주 에이전트에도 같은 판단을 전달합니다. | 터미널 입력을 읽거나 몰래 명령을 입력하지 않고, 터미널 설정·입력 모드를 바꾸지 않습니다. |
| 설치·업데이트·삭제 | 사용자 영역의 자체 실행 파일·소스, 사용자용 백그라운드 서비스·자동 시작 항목, Memory Supervisor가 소유한 Hook·스킬 연결, 설정·상태 파일만 설치·갱신·삭제합니다. | 프로젝트 파일, 커널, 드라이버, 방화벽, 운영체제 메모리·스왑 설정은 변경하지 않습니다. 삭제도 사용자가 `uninstall`을 직접 실행한 경우에만 시작합니다. |
| 사용자가 선택하는 설정 | 기본값에는 고정 메모리 한도가 없습니다. `budget set`, `on`·`off`, 수동 `resume`, `terminate`·`kill`, 알림 설정은 사용자가 해당 명령을 실행할 때만 바뀝니다. | 선택형 한도나 종료 명령을 자동으로 켜지 않습니다. |
| 보호 장치 | Hook 판단이 없거나 오래됐으면 그 판단을 버리고 작업을 통과시키면서 보호 기능을 사용할 수 없다고 알립니다. 프로세스 제어 직전에는 PID와 시작 정보를 다시 확인합니다. 정확한 터미널에 알림을 남길 수 없거나 조치 기록을 저장할 수 없으면 리드를 멈추지 않거나 즉시 재개합니다. | 오래된 판단으로 작업을 계속 막거나 기록되지 않은 일시정지를 남기지 않습니다. 자동 물리 조치는 확인된 Claude Code·Codex 작업 프로세스의 가역적인 일시정지를 넘지 않습니다. |

**Memory Supervisor가 확인하고 제어하는 것은 이 표까지입니다.** 프로젝트 파일과 프로세스
메모리를 직접 열어 읽지 않습니다. Hook 이벤트에 함께 들어올 수 있는 프롬프트·대화·모델 응답과
파일 내용은 추출하거나 제어 판단에 사용하지 않고 로컬 상태·federation·Discord·Telegram 알림
어디에도 넣지 않습니다. 브라우저·IDE 내부 데이터와 Claude·ChatGPT 인증 정보도 다루지 않습니다.
