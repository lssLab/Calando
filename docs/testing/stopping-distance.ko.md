# 적응형 제동거리

<p align="center">
  <a href="stopping-distance.md">English</a> · <strong>한국어</strong>
</p>

Memory Supervisor의 목적은 메모리 사용량을 낮게 유지하는 것이 아닙니다. 메모리 여유가 줄어도
감소 속도가 안정적이면 실행 중인 작업을 그대로 두고, 실제 위험이 가까워질 때만 새 작업부터
단계적으로 줄입니다.

## 계산 기준

```text
반응 시간          = max(3초, 센서 주기 × 5)
최소 복구 여유     = 감지 용량의 0.5%, 단 256–1024 MiB 범위
확인된 감소 속도   = 지속된 물리 메모리·commit·추적 작업 속도 중 가장 큰 값
                      (같은 증가를 중복 합산하지 않음)
자동 복구 여유     = 최소 복구 여유 + 확인된 감소 속도 × 반응 시간
                      (감지 용량의 최대 25%)
새 작업 시작 여유  = 자동 복구 여유 + 최소 작업 블록 하나
                      (감지 용량의 최대 30%)
```

비율은 잘못 튄 측정값이 기준을 지나치게 키우지 않도록 막는 상한입니다. 실제 판단은 남은 메모리,
감소 속도, 운영체제의 부족 신호, 현재 속도로 복구 여유에 닿기까지 남은 시간을 함께 사용합니다.

- `ALLOW / OBSERVE`: 기존 작업과 새 작업을 제한하지 않습니다.
- `HOLD`: 위험까지 약 두 번의 반응 구간만 남거나 새 작업 하나를 시작할 여유가 없을 때 새 확장만
  기다립니다.
- `DRAIN`: 확인된 감소가 한 반응 구간 안에 복구 여유에 닿을 때, 원인이 확인된 작업의 앞으로 할
  일만 필요한 만큼 줄입니다.
- 외부 프로그램이 원인이거나 원인을 특정하지 못하면 AI 작업을 임의로 일시정지하지 않습니다.
- 로컬 프로그램 일시정지는 위 단계로도 증가가 멈추지 않고 정확한 대상을 확인한 경우에만 쓰는
  최후의 보호 단계입니다.

따라서 높은 사용량 자체가 제동 이유는 아닙니다. 느리고 안정적인 작업은 계속 실행하고, 빠르게
줄어드는 상황에서는 측정된 속도만큼 더 긴 제동거리를 확보합니다.

## 통제된 실머신 검증

| 항목 | 환경 |
| --- | --- |
| Host | Windows 11 Pro, RAM 15.73 GiB, Intel i5-1135G7, 논리 CPU 8개 |
| Guest | WSL2 Ubuntu, x86-64 |
| 테스트 커널이 감지한 용량 | 7,941 MiB |
| Swap | 16 GiB |
| AI 도구 | Claude Code 2.1.217, Codex CLI 0.145.0 |
| Supervisor | Rust `0.2.0-alpha.1`, 1초 센서 주기, 사용자 메모리 상한 꺼짐 |

AI 프로세스 밖의 제한된 메모리 할당기가 실제 메모리를 약 64 MiB/s로 사용하다가 여유가 1 GiB
아래로 내려가면 약 32 MiB/s로 낮췄습니다. 350 MiB에서 증가를 멈추고 20초 뒤 전부 반환했습니다.
외부 프로그램이 만든 압력이므로 올바른 결과는 새 작업만 제동하고 Claude Code나 Codex를 원인으로
잘못 지목하지 않는 것입니다.

| 지점 | 확인된 결과 |
| --- | --- |
| 시작 | 가용 5,910 MiB, 기존 작업 제한 없음 |
| 첫 제동 | 가용 1,143 MiB, 자동 복구 여유 577.6 MiB, 도달 예상 8.8초에서 `HOLD` |
| 다음 제동 | 가용 530 MiB, 자동 복구 여유 409.6 MiB, 도달 예상 3.9초에서 `DRAIN` |
| `DRAIN` 중 | 새 서브에이전트 시작은 대기, 진행 중인 편집은 허용 |
| 최저점 | 약 350 MiB, 터미널 동결·강제 종료 없음 |
| 대상 판별 | 외부 압력으로 판별, 제한된 에이전트와 일시정지한 PID 없음 |
| 복구 | 할당 해제 뒤 가용 5,902 MiB, 안정 구간을 확인한 뒤 새 작업 자동 재개 |

## 규모 검증

결정적 Rust 테스트는 512 MiB부터 10 TiB까지의 용량과 1 MiB/s부터 128 GiB/s까지의 지속 감소
속도에서 같은 시간 관계를 확인합니다. 복구 여유까지 12초가 남으면 `DRAIN`에 들어가지 않고,
7초에서는 `HOLD`, 4초에서는 `DRAIN`이 됩니다. 다수 에이전트 상황에서는 남은 단계와 시간을
계산해 매 주기 필요한 최소 대상만 줄이고, 상황이 좋아지는 즉시 다음 제한을 중단하는지도
검증합니다.

## 검증 범위의 한계

- 실머신 근접 테스트는 한 Windows+WSL2 환경에서 외부 압력과 자동 복구를 확인한 결과입니다.
- 다수 에이전트와 매우 큰 메모리 용량은 결정적 시뮬레이션으로 검증합니다.
- 프로세스를 일시정지하면 추가 증가는 멈추지만 이미 사용한 메모리가 즉시 반환되지는 않습니다.
- Windows용 공개 실행 파일은 신뢰된 코드 서명이 준비되기 전까지 Windows 보안 설정에 따라 실행이
  차단될 수 있습니다. 자세한 내용은 [Windows 실행 신뢰 안내](../guides/windows-signing.ko.md)를
  확인하세요.
